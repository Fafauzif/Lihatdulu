# Current project brief · 20 November 2026 (scan direction updated 22 November)

LihatDulu is an Indonesian used-furniture marketplace concept for a competition. Help buyers find furniture by **category, price, condition, location and fit**, then inspect it with photos and 3D where available. Let a seller capture a physical item from the website and preview the result as a buyer.

**Authority** — Latest owner direction, current checkout and fresh tests, this brief plus the decision log, then the active introduction of the [original V8 pack](LihatDulu_MASTER_AI_CONTEXT_v8_0_2026-10-16.md). Historical sections of that pack are for provenance. The pack describes a ZIP with an `app/` subtree. The verified GitHub baseline is a flat Vite checkout and contains no root `vercel.json`, `AGENTS.md`, or the other ZIP-specific design documents.

- **Inventory** — Ten active authored examples, two coming soon, four authored 3D/room models. Keep existing IDs, prices, media provenance, dimensions, eligibility and routes. The seller Sora example plays a prepared 18-second clip. It comes from a different workflow from the new real scan.
- **Buyer experience** — Gallery-first details, inspectable condition, transparent cost breakdown, local saved lists/offers/checkout review. Keep 3D opening motions and room fit grounded in the authored GLBs and their geometry. Local buyer actions remain demo behavior.
- **Marketplace correction** — The owner experienced the app as a showcase without obvious search filters or categories. The checkout already renders a desktop rail and category chips, and hides the original rail at widths ≤1,050 px. The priority is actual discoverability on the usual entry paths. White canvas and green accents are the approved direction to evaluate, with comparison screenshots and deliberate catalog density.
- **New scan** — KIRI Engine cloud does the reconstruction. The prototype at `/jual/pindai` starts upload-only: choose an existing MP4, preview it, confirm that it goes to KIRI, then watch upload/queue/process and open the saved splat at `/pindai/:id`. The server owns the key, downloads the ZIP, validates the PLY, converts it with the pinned converter and stores the SPZ locally. There is an explicitly labelled mock mode; no real credit has been spent. The phone camera is deferred until one real clip passes end-to-end. The previous local FFmpeg → COLMAP → Brush worker is retired.
- **Equipment** — KIRI does the GPU work, so the demo laptop only needs Node and a browser. The earlier Helios/RTX study is historical evidence in [scan-toolchain.md](../scan-toolchain.md), not a runtime requirement. The real clip, phone model, browser, network and KIRI turnaround are still unmeasured.
- **Handoff scope** — This overlay brings the briefs, tools and visual evidence for new sessions. The buyer and seller runtime at the checked Git commit precedes these plans.
